1. Learn the optimizer separately from the model

Linear regression specifies a prediction function. Ordinary least squares specifies an objective. Gradient descent specifies one way to optimize that objective. These are distinct choices: replacing a direct least-squares solve with gradient descent does not create a different statistical objective if the same loss is optimized to the same solution.

Iterative methods are useful when direct factorization is expensive, when data arrives in batches, or when the same optimization ideas must extend to models without a convenient closed-form solution. For a small dense regression problem, a stable least-squares solver is usually simpler. This tutorial uses linear regression because its convex quadratic structure lets us verify every optimization step.

You will derive scalar and matrix gradients, calculate an update by hand, understand a learning-rate bound, and compare a converged NumPy implementation with a direct solution. Prerequisites are basic derivatives, matrix multiplication, and the squared-error objective.

2. Follow the local slope downhill

A gradient points in the direction of steepest local increase under the Euclidean geometry of parameter space. To reduce a differentiable objective, move in the opposite direction. The learning rate determines how far to move. A very small step can be safe but slow; a large step can overshoot the minimum and increase the loss.

Feature scaling changes the shape of the loss surface in coefficient coordinates. A long narrow valley forces a single learning rate to accommodate both steep and shallow directions. Standardization often improves conditioning, although correlations can leave difficult directions even after each column has unit variance.

\hat y_i=\beta_0+\sum_{j=1}^p x_{ij}\beta_j,\qquad J=\frac1{2n}\sum_i(\hat y_i-y_i)^2

There are n rows and p feature coefficients. The 1/2 factor cancels the factor two from differentiating a square. It does not alter the minimizer compared with MSE, but it changes gradient magnitude and therefore the numerical meaning of a fixed learning rate.

3. Derive the gradient with the chain rule

For observation i, write rᵢ = y-hatᵢ − yᵢ. This is prediction minus target, the negative of the residual convention used elsewhere. The derivative of rᵢ²/2 with respect to rᵢ is rᵢ. The prediction derivative with respect to the intercept is one, and with respect to slope βⱼ is xᵢⱼ.

\frac{\partial J}{\partial\beta_0}=\frac1n\sum_i r_i,\qquad\frac{\partial J}{\partial\beta_j}=\frac1n\sum_i x_{ij}r_i

Include the intercept as a column of ones in design matrix A, and collect all coefficients in θ. Then the gradient and update are:

\nabla J(\boldsymbol\theta)=\frac1nA^T(A\boldsymbol\theta-\mathbf y),\qquad\boldsymbol\theta_{t+1}=\boldsymbol\theta_t-\eta\nabla J(\boldsymbol\theta_t)

The step index is t and the positive learning rate is η. Compute the full gradient from the current parameter vector, then update all coordinates together. Updating one coefficient and using its changed value while calculating the next derivative is a different procedure unless deliberately designed as coordinate descent.

4. Why the learning rate has a limit

The Hessian, or matrix of second derivatives, is H = AᵀA/n. It is positive semidefinite. Around a solution θ*, the parameter error evolves by multiplication with I − ηH. In each eigenvector direction with positive eigenvalue h, the error is multiplied by 1 − ηh per update.

\boldsymbol\theta_{t+1}-\boldsymbol\theta^*=(I-\eta H)(\boldsymbol\theta_t-\boldsymbol\theta^*),\qquad 0<\eta<\frac2{\lambda_{\max}(H)}

The symbol λmax(H) here denotes the largest Hessian eigenvalue, not a regularization strength. The inequality keeps every positive-curvature multiplier's magnitude below one. For a full-rank quadratic, it gives convergence of fixed-step gradient descent. If H has zero eigenvalues, directions in its null space are not identified by the loss; initialization influences which coefficient solution is reached.

A safe teaching choice is η = 1/λmax(H). Computing the largest eigenvalue can itself be expensive for huge systems, so production algorithms use other step-size or preconditioning strategies. The bound applies to this specific half-MSE objective; changing loss normalization changes H and the bound.

5. Calculate one update and its effect

Take x = [1,2], y = [2,4], n = 2, and initialize intercept and slope to zero. Predictions are [0,0], so prediction errors r = [−2,−4]. The intercept gradient is (−2 − 4)/2 = −3; the slope gradient is (1·−2 + 2·−4)/2 = −5.

With η = 0.1, the new intercept is 0.3 and the new slope is 0.5. Predictions become [0.8,1.3]. Residuals y − y-hat are [1.2,2.7], squared errors [1.44,7.29], MSE = 4.365, and half-MSE = 2.1825. The initial half-MSE was (4 + 16)/4 = 5, so this update reduced the objective.

The fitted parameters are not yet the optimum [0,2]. Gradient descent needs more updates. A new x = 3 currently receives prediction 0.3 + 0.5·3 = 1.8; if its target is 6, the error is large. An intermediate optimizer state is not a finished estimator merely because its training loss decreased once.

6. See convergence and divergence

The lab isolates a one-parameter problem with unit curvature. Its exact stability boundary is η = 2. Below the boundary, updates contract toward the minimum; at the boundary they oscillate without reducing the error; above it they diverge. The vertical axis rescales, so read the numeric loss as well as the curve.

7. Batch gradient descent from scratch

The script standardizes features using training statistics, adds an intercept column, computes a safe step size, and checks gradient norm for convergence. It compares final predictions with a direct least-squares solution and scikit-learn. The plot shows the objective during optimization, rather than presenting an invented benchmark.

"""Run with Python 3 after installing examples/requirements.txt."""
import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LinearRegression

rng = np.random.default_rng(42)
X = rng.normal(size=(240, 3)) * np.array([1, 10, 100])
y = 2 + X @ np.array([2, -0.3, 0.01]) + rng.normal(0, 0.5, 240)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42
)
scaler = StandardScaler().fit(X_train)
Z_train = scaler.transform(X_train)
Z_test = scaler.transform(X_test)
A = np.column_stack([np.ones(len(Z_train)), Z_train])
A_test = np.column_stack([np.ones(len(Z_test)), Z_test])
n = len(A)
hessian = A.T @ A / n
rate = 1 / np.linalg.eigvalsh(hessian).max()
theta = np.zeros(A.shape[1])
losses = []
for iteration in range(10000):
    error = A @ theta - y_train
    losses.append(0.5 * np.mean(error ** 2))
    gradient = A.T @ error / n
    if np.linalg.norm(gradient) < 1e-9:
        break
    theta -= rate * gradient
else:
    raise RuntimeError("Gradient descent did not converge")
exact = np.linalg.lstsq(A, y_train, rcond=None)[0]
np.testing.assert_allclose(theta, exact, atol=1e-7)
pred = A_test @ theta
model = LinearRegression().fit(Z_train, y_train)
np.testing.assert_allclose(pred, model.predict(Z_test), atol=1e-7)
assert np.all(np.diff(losses) <= 1e-10)
print("Learning rate:", rate, "Updates:", iteration)

print("Test MAE:", mean_absolute_error(y_test, pred))
print("Test RMSE:", np.sqrt(mean_squared_error(y_test, pred)))
print("Test R2:", r2_score(y_test, pred))

plt.plot(losses)
plt.xlabel("Batch gradient update")
plt.ylabel("Training half-MSE")
plt.title("Convergence of the stated objective")
plt.tight_layout()
plt.show()

A small change in loss can be a misleading stopping rule when progress is slow because of ill-conditioning. Checking gradient norm, a maximum iteration budget, and agreement with a known solution on a test problem provides a clearer diagnostic. Report failure to converge instead of silently returning an arbitrary last iterate.

8. Batch, stochastic, and mini-batch updates

Batch gradient descent computes the exact empirical gradient over all n training observations for every update, costing roughly O(np) per dense pass. Stochastic gradient descent uses one sampled observation; mini-batch descent uses a subset. Their updates are noisy estimates of the full gradient, and step-size schedules become important.

Shuffling and fixed random seeds help reproducibility for stochastic methods, but a fixed seed is not a statistical guarantee. For streaming data, changing distributions and feature scaling require additional design. A model trained with an online method must not silently recompute scaling on future evaluation rows.

Early stopping can behave like implicit regularization because weakly identified directions may be learned slowly. That is a property of an incomplete optimization trajectory and its initialization, not equivalence to every possible ridge penalty. Distinguish deliberate early stopping selected on validation data from an optimizer that accidentally failed to converge.

Check gradients numerically

A central finite difference approximates one partial derivative by perturbing a coefficient in both directions. Let eⱼ be a vector with a one at coordinate j and zeros elsewhere, and let h be a small positive step. Compare the analytic gradient with [J(θ + heⱼ) − J(θ − heⱼ)]/(2h).

\frac{\partial J}{\partial\theta_j}\approx\frac{J(\boldsymbol\theta+h\mathbf e_j)-J(\boldsymbol\theta-h\mathbf e_j)}{2h}

For the exact quadratic in this tutorial, truncation behaviour is especially simple, but floating-point cancellation still matters. Making h extremely tiny subtracts nearly equal values and can worsen the estimate. Use several moderate scales and compare relative as well as absolute error, particularly when true derivatives are close to zero.

This check can expose a missing factor n, an incorrect residual sign, or an intercept column omitted from the gradient. It cannot establish that the dataset or evaluation design is correct. Numerical differentiation validates the relationship between the implemented objective and gradient, not the modelling claim around them.

Derive the effect of adding ridge

Suppose the half-MSE objective is augmented with λ‖β‖²/2, where β excludes the intercept. The slope gradient gains λβ, while the intercept gradient remains the mean prediction error. In an augmented parameter vector, a diagonal mask with zero for the intercept and ones for slopes represents this distinction.

\nabla J_{\rm reg}(\boldsymbol\theta)=\frac1nA^T(A\boldsymbol\theta-\mathbf y)+\lambda D\boldsymbol\theta,\qquad D=\operatorname{diag}(0,1,\ldots,1)

The Hessian becomes AᵀA/n + λD, so the stable fixed learning rate must be reconsidered. Reusing a step size computed for an unregularized objective can be too aggressive after adding curvature. The penalty may improve conditioning by lifting weak slope directions while also increasing the largest eigenvalue.

Interpret learning curves correctly

An optimization trace plots loss against update count for one training dataset. A statistical learning curve plots performance against training sample count. They answer different questions. A descending optimization curve shows that a solver is making progress; it does not show that collecting more data would help or that the model is generalizing.

When comparing batch and mini-batch methods, iteration counts are not directly comparable because one batch update may process the entire dataset while one mini-batch update processes only a small fraction. Compare epochs, processed examples, or measured runtime with the computational environment stated. Do not infer an efficiency ranking merely from which curve reaches a low value in fewer plotted steps.

9. Interview questions

1. Is gradient descent a regression model?

No. It is an optimization algorithm that can minimize many differentiable objectives, including the squared loss of linear regression.

2. Why include 1/2 in the loss?

It cancels the derivative's factor two. The optimum is unchanged, but gradient scale and a compatible learning rate change.

3. What controls the stable learning rate?

For the fixed-step quadratic problem, the largest Hessian eigenvalue gives the bound η < 2/λmax(H).

4. Why standardize features?

It can reduce disparities in curvature caused by units, improving convergence. Strong correlations may still cause poor conditioning.

5. Can the objective be convex without a unique coefficient solution?

Yes. A rank-deficient design gives a convex but not strictly convex quadratic, with flat directions and potentially many minimizers.

6. Why update all coordinates simultaneously?

The batch-gradient formula evaluates every derivative at the same current vector. Sequentially changing that vector alters the algorithm.

7. How does stochastic descent differ?

It uses sampled gradients, reducing work per update while introducing noise and often requiring a learning-rate schedule.

8. Does decreasing training loss guarantee generalization?

No. It only describes optimization on the training objective. Generalization requires separate evaluation.

10. Practice and takeaways

  • Verify the scalar derivative with finite differences at several coefficients, using small but not excessively tiny perturbations.
  • Remove scaling and multiply one feature by 1,000. Recalculate the stability bound and compare convergence.
  • Implement mini-batch descent and compare its noisy loss trajectory with batch descent under a fixed data split.
  • Build an optimizer mini-lab that reports gradient norm, iteration count, and objective normalization alongside learning rate.

Optimization correctness starts with a precisely stated objective. The gradient, step-size scale, stopping rule, and numerical checks should all refer to that same objective.
