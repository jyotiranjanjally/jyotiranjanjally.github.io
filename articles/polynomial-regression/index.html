Polynomial Regression — Nonlinear Relationships

1. Curved relationships, linear parameters

A straight line may miss the relationship between speed and energy consumption or temperature and equipment performance. Polynomial regression adds powers of a feature so a linear estimator can represent curvature. The result is nonlinear in the original input, but still linear in the coefficients being estimated.

This distinction matters: you can use ordinary least squares, ridge, or another linear estimator after creating the polynomial features. You do not need a general nonlinear optimizer merely because the prediction curve bends. This tutorial derives the feature expansion, explains the risk of high degree, and implements a pipeline that keeps preprocessing inside each validation fold.

Prerequisites are simple regression and the design-matrix interpretation. You will choose a degree using validation, compare underfitting and overfitting, and inspect numerical conditioning rather than judging a model only by how smoothly it passes through the training points.

2. Give the model curved building blocks

A linear model with only x can tilt and shift a line. Adding x² gives it a symmetric curved component. Adding x³ allows an asymmetric change in curvature. Each new column is a fixed function of the input; training still chooses only how much of each column to use.

\hat y=\beta_0+\beta_1x+\beta_2x^2+\cdots+\beta_dx^d=\boldsymbol\phi(x)^T\boldsymbol\beta

The nonnegative integer d is the maximum degree. The vector φ(x) = [1, x, x², …, xᵈ] is the polynomial feature map, and β contains d + 1 coefficients. Increasing d expands the set of functions available to the model. It also creates more opportunities to fit noise.

“Linear in parameters” means that doubling every coefficient doubles the prediction, and adding two coefficient vectors adds their predictions. A term such as exp(βx) is nonlinear in β; x² multiplied by β is not. This algebraic distinction determines which optimization tools apply.

3. Fit the expanded design matrix

For n observations, stack the feature-map vectors into a matrix Φ. Its row i contains the powers of xᵢ. The least-squares objective and its derivative have the same form as multiple linear regression.

J(\boldsymbol\beta)=\frac1n\|\mathbf y-\Phi\boldsymbol\beta\|_2^2,\qquad\nabla J=\frac2n\Phi^T(\Phi\boldsymbol\beta-\mathbf y)
\Phi^T\Phi\hat{\boldsymbol\beta}=\Phi^T\mathbf y

Here Φ has n rows and d + 1 columns. A unique ordinary least-squares coefficient vector requires full column rank. If d + 1 exceeds the number of distinct observed feature values, uniqueness is impossible. Even when rank is technically full, powers of similar or very large values can be numerically ill-conditioned.

For example, if x is around 10,000, x⁶ is around 10²⁴. Columns of such different magnitudes and strong correlations can amplify floating-point error. Centering and scaling the input before expanding its powers helps; scaling expanded columns is also relevant when a regularization penalty should compare coefficients on comparable feature scales. Orthogonal polynomial bases and splines are alternatives when raw powers become unwieldy.

4. A quadratic fit by hand

Take x = [−1, 0, 1] and y = [2, 1, 2]. With degree two, the three equations are β₀ − β₁ + β₂ = 2, β₀ = 1, and β₀ + β₁ + β₂ = 2. Substituting β₀ = 1 gives −β₁ + β₂ = 1 and β₁ + β₂ = 1. Adding them yields β₂ = 1, then β₁ = 0.

The fitted model is y-hat = 1 + x². Training predictions are [2,1,2], residuals are all zero, and training MSE is zero. At x = 0.5, it predicts 1.25. If the observed target there is 1.5, residual = 0.25 and squared error = 0.0625.

A degree-one model on the same symmetric data has slope zero and intercept 5/3. Its residuals are [1/3, −2/3, 1/3], so squared error sums to 2/3 and MSE = 2/9. The quadratic fits the visible curvature better. With only three points, however, exact interpolation does not establish that the quadratic is the correct future relationship.

5. Degree, noise, and fit

The lab fits coefficients to the displayed observations for each degree. Increasing degree cannot worsen the mathematical minimum training squared error when the lower-degree function remains in the larger hypothesis class. Finite precision can complicate that statement in software. More importantly, the graph's training error says nothing by itself about performance on new observations.

6. Underfitting, overfitting, and extrapolation

A degree-one model can underfit a curved conditional mean: systematic residual structure remains even with abundant data. A very high-degree polynomial can overfit finite-sample noise: small changes to observations produce large changes to the curve. The usual bias–variance picture describes these tendencies across repeated training samples, not a universal monotonic law for every dataset.

High-degree polynomials are particularly risky outside the training interval. The leading power eventually dominates, so an apparently modest curve over the data range can explode just beyond it. Standardizing inputs does not remove that structural extrapolation risk. It changes numerical conditioning, not the fact that powers grow.

Degree should be chosen using a validation strategy that resembles deployment. Random K-fold validation is appropriate only when observations are reasonably exchangeable. For time-dependent measurements, a chronological split is often more defensible. Report the final chosen degree and evaluate once on a test set that played no role in degree selection.

7. A leakage-safe polynomial pipeline

The complete script compares degrees one through six. The feature scaler, polynomial expansion, second scaler, and ridge estimator form one pipeline. Grid search refits the learned transformations separately within every training fold. The example uses a small fixed ridge penalty for numerical stability; this makes it regularized polynomial regression rather than pure polynomial OLS.

"""Run with Python 3 after installing examples/requirements.txt."""
import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, PolynomialFeatures
from sklearn.linear_model import Ridge
from sklearn.model_selection import GridSearchCV, KFold

rng = np.random.default_rng(42)
X = rng.uniform(-2, 2, size=(200, 1))
y = 1 + 0.5 * X[:, 0] + 2 * X[:, 0] ** 2 + rng.normal(0, 0.7, 200)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42
)
pipe = Pipeline([
    ("input_scale", StandardScaler()),
    ("poly", PolynomialFeatures(include_bias=False)),
    ("feature_scale", StandardScaler()),
    ("model", Ridge(alpha=0.01)),
])
search = GridSearchCV(pipe, {"poly__degree": list(range(1, 7))},
                      scoring="neg_mean_squared_error",
                      cv=KFold(5, shuffle=True, random_state=42))
search.fit(X_train, y_train)
pred = search.predict(X_test)
print("Selected degree:", search.best_params_["poly__degree"])

print("Test MAE:", mean_absolute_error(y_test, pred))
print("Test RMSE:", np.sqrt(mean_squared_error(y_test, pred)))
print("Test R2:", r2_score(y_test, pred))

grid = np.linspace(-2, 2, 300).reshape(-1, 1)
plt.scatter(X_test[:, 0], y_test, label="Test observations")
plt.plot(grid[:, 0], search.predict(grid), color="tab:orange", label="Selected polynomial")
plt.xlabel("x")
plt.ylabel("y")
plt.legend()
plt.tight_layout()
plt.show()

There is no separate constant column from PolynomialFeatures because include_bias=False. The final estimator supplies an unpenalized intercept. If you enable both, you create a redundant constant feature that is usually unnecessary. The plot overlays selected-model predictions over a grid inside the observed feature interval.

8. When the method helps

Polynomial features provide an inexpensive way to add modest curvature while reusing linear-model tooling. They can be useful for calibration over a bounded operating range or as a transparent baseline. A quadratic coefficient can sometimes express a known physical shape, although empirical fitting alone does not establish a physical law.

With p original features and all terms through total degree d, the number of terms including the constant is the binomial coefficient (p + d choose d). Interactions rapidly increase memory and fitting cost. A degree that is cheap for one input may be impractical for dozens. Avoid interpreting an isolated coefficient without considering the other powers and interactions.

Splines give more local control; tree methods can capture thresholds and interactions; a domain model may impose meaningful shape constraints. These alternatives should be evaluated against the same baseline and split, rather than selected because a more complicated curve looks impressive.

Centering changes coefficients, not the underlying polynomial space

Let u = (x − m)/s, where m is a training mean and s is a positive training scale. A quadratic fitted in u has prediction a₀ + a₁u + a₂u². Expanding the powers expresses the same function in raw x coordinates. The raw quadratic coefficient is a₂/s², the raw linear coefficient is a₁/s − 2a₂m/s², and the raw intercept is a₀ − a₁m/s + a₂m²/s².

This explains why coefficients from standardized and raw-power fits should not be compared entry by entry. Even the linear coefficient changes when a quadratic term is present. If the transformation is invertible and no penalty is imposed, both parameterizations span the same quadratic functions. Regularization changes that conclusion about the preferred fit because the coefficient norm is measured in a different coordinate system.

For example, with m = 2, s = 2, and a = [1,0,4], the standardized model is 1 + 4((x − 2)/2)² = 1 + (x − 2)² = 5 − 4x + x². The raw intercept is 5, the raw slope is −4, and the quadratic coefficient is 1. At x = 3 both parameterizations predict 2. The apparent coefficient differences are entirely due to representation.

Differentiate the fitted curve to interpret local behaviour

\frac{d\hat y}{dx}=\beta_1+2\beta_2x+\cdots+d\beta_dx^{d-1}

The derivative is a local rate of change in target units per input unit. In the worked quadratic 1 + x², it is 2x: negative to the left of zero, zero at the minimum, and positive to the right. A single coefficient cannot summarize that changing slope. When an application requires monotonicity, an unconstrained polynomial may violate it even while producing a good average score.

Derivative estimates are often more sensitive to noise than function predictions, especially for high-degree models. A visually smooth fitted curve does not guarantee a reliable estimated turning point. If the turning point drives an operating decision, validate that derived quantity and consider a model with a defensible shape constraint.

Validate complexity as a procedure

Plotting many degrees against the test targets and selecting the most convincing curve is test-set tuning even if no explicit score is computed. Choose degree using training-only validation, then use the test plot as an audit of the fixed choice. If the audit reveals a reason to redesign the model, acknowledge that the next iteration needs a fresh final evaluation boundary.

9. Interview questions

1. Why is polynomial regression still a linear model?

The prediction is a linear combination of fixed transformed features. The coefficients appear to the first power and are not multiplied together.

2. What does degree control?

The maximum power, and thus the size and flexibility of the basis. It is a hyperparameter, not a coefficient learned by ordinary least squares.

3. Does higher degree always lower test error?

No. It enlarges the training function class but can increase estimation variance, numerical instability, and extrapolation error.

4. Why scale before expansion?

Keeping input magnitudes moderate reduces extreme powers and can improve conditioning. Scaling expanded features additionally defines how regularization compares their coefficients.

5. What is the multivariate feature-count problem?

All polynomial interactions through degree d create a combinatorial number of columns, increasing memory, computation, and the risk of fitting noise.

6. Should the bias column be penalized?

Usually no. Use an estimator-provided intercept and omit the polynomial bias column unless you have an explicit reason for another parameterization.

7. Can a degree-two model capture interactions?

With multiple inputs, a full polynomial expansion can include products such as x₁x₂ as well as squares. These allow the fitted effect of one input to depend on another.

8. Why might a spline be preferable?

Local basis functions can model curvature without forcing one global polynomial to determine behaviour across the entire domain.

10. Practice and takeaways

  • Run the example with several random seeds. Compare the selected degree and final error without selecting a seed based on its score.
  • Extend the plotted grid outside the training interval. Explain why uncertainty about extrapolation is not captured by training MSE.
  • Compare polynomial ridge with an unregularized fit using the same degree and split.
  • Build a bounded-range sensor-calibration mini-project and record the operating range in the model's interface.

Feature expansion changes the functions a model can express. Validation chooses whether that flexibility is useful. Stable numerics and sensible domain limits remain essential even when the optimizer is still linear least squares.
