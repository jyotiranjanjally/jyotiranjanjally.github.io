1. Stabilize a sensitive least-squares fit

When several features carry nearly the same information, ordinary least squares can assign large positive and negative coefficients that cancel on the training data. Small changes to the observations may then cause large coefficient changes. Ridge regression discourages this behaviour by adding a squared-coefficient penalty to the loss.

Ridge is useful for correlated measurements, many weak predictors, and polynomial feature sets. It deliberately introduces bias to reduce sensitivity. Whether that trade-off improves prediction is an empirical question for validation, not a theorem about every dataset.

You will derive the ridge solution, understand shrinkage along singular directions, work a numerical example, and match a mathematical λ to scikit-learn's alpha. Prerequisites are matrix regression and differentiation of a quadratic form.

2. Pay for coefficient magnitude

Least squares rewards any coefficient change that lowers residual error. Ridge asks whether that improvement is worth the increase in coefficient magnitude. A large coefficient is not inherently wrong, but without regularization a noisy direction can receive a large coefficient simply because it improves training fit.

Feature units matter. A one-unit coefficient on a feature measured in kilometres is not comparable to one on the same feature measured in metres. Standardizing features using training statistics makes the penalty's scale more consistent across columns. It is a modelling choice: the penalty expresses a preference for small coefficients in that chosen coordinate system.

\min_{\beta_0,\boldsymbol\beta}\left[\frac1n\sum_{i=1}^n(y_i-\beta_0-\mathbf x_i^T\boldsymbol\beta)^2+\lambda\sum_{j=1}^p\beta_j^2\right],\qquad\lambda\geq0

There are n observations and p slopes. The intercept β₀ is excluded from the penalty. The nonnegative λ controls the trade-off. At λ = 0 the objective reduces to ordinary least squares. As λ grows, slope estimates are more strongly discouraged, and the prediction tends toward a constant model under standard centered conditions.

3. Center, differentiate, and solve

Let Xc be the feature matrix after subtracting each training feature mean, and yc the target vector after subtracting its training mean. Optimizing the unpenalized intercept gives β₀ = y-bar − x-barᵀβ. We can therefore solve for slopes using centered data, then reconstruct the intercept.

J(\boldsymbol\beta)=\frac1n\|\mathbf y_c-X_c\boldsymbol\beta\|_2^2+\lambda\boldsymbol\beta^T\boldsymbol\beta
\nabla J=\frac2nX_c^T(X_c\boldsymbol\beta-\mathbf y_c)+2\lambda\boldsymbol\beta=0

Multiply by n/2 and collect β. The identity matrix I has p rows and columns; adding nλI increases every eigenvalue of the Gram matrix by nλ.

(X_c^TX_c+n\lambda I)\hat{\boldsymbol\beta}=X_c^T\mathbf y_c

For λ > 0, the matrix is positive definite even if feature columns are dependent. The slope solution is unique. In software, solve the linear system rather than constructing an explicit inverse. The mathematical inverse notation describes the solution but does not prescribe the best algorithm.

4. What exactly is being shrunk?

Write the centered feature matrix as UDVᵀ, where D contains singular values sk. Along the k-th singular direction, ordinary least squares divides the corresponding target projection by sk. Ridge replaces that factor with sk/(sk² + nλ).

\hat{\boldsymbol\beta}_{\rm ridge}=V\operatorname{diag}\!\left(\frac{s_k}{s_k^2+n\lambda}\right)U^T\mathbf y_c

Small singular values represent weakly supported feature directions. The ordinary inverse can amplify noise in those directions; ridge suppresses it. Compared with the OLS coefficient in a nonzero singular direction, the multiplier is sk²/(sk² + nλ), which lies between zero and one.

This is shrinkage in the singular-vector basis. Individual coefficients in the original correlated-feature basis need not decrease monotonically as λ changes. Their combinations are being stabilized. In the special case of centered orthonormal columns, XᵀX/n = I, every coefficient has the simpler form β-hatj = zj/(1 + λ), where z = Xᵀy/n is the OLS coefficient vector.

5. Calculate a ridge fit

Use x = [−1, 0, 1] and y = [−2, 0, 2]. Both means are zero, so the intercept is zero. There are n = 3 rows, xᵀx = 2, and xᵀy = 4. Ordinary least squares gives slope 2.

With λ = 2/3 under our MSE convention, nλ = 2. The ridge slope is 4/(2 + 2) = 1. Predictions are [−1, 0, 1], residuals [−1, 0, 1], and MSE = 2/3. The penalty is (2/3)·1² = 2/3, giving total objective 4/3. At the OLS slope 2, MSE is zero but the penalty is 8/3, a larger objective.

At x = 2, ridge predicts 2. If the true relationship remains y = 2x, the true target would be 4 and this prediction has squared error 4. This noiseless example demonstrates deliberate bias; it is not evidence that ridge always improves accuracy. Its advantage arises when variance reduction compensates for that bias in noisy finite samples.

6. Inspect coefficient paths

The plotted paths use the orthonormal special case so every value can be computed exactly. They should not be mistaken for a fitted path on arbitrary correlated data. Unlike lasso, ridge does not generally create exact zeros at a finite positive penalty; coefficients approach zero continuously.

7. Match the library's objective

Scikit-learn's Ridge minimizes residual sum of squares plus alpha times the squared coefficient norm. Multiplying this tutorial's objective by n leaves its minimizer unchanged, so the corresponding library parameter is alpha = n_train * lambda. A library using half-MSE would require a different translation.

"""Run with Python 3 after installing examples/requirements.txt."""
import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
from sklearn.linear_model import Ridge

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(42)
X = rng.normal(size=(260, 6))
X[:, 1] = 0.8 * X[:, 0] + 0.2 * X[:, 1]
y = 2 + X @ np.array([2.5, 1.5, 0, 0, -1, 0]) + rng.normal(0, 0.8, 260)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42
)
scaler = StandardScaler().fit(X_train)
Z = scaler.transform(X_train)
Z_test = scaler.transform(X_test)
y_mean = y_train.mean()
yc = y_train - y_mean
n, p = Z.shape

lam = 0.1
beta = np.linalg.solve(Z.T @ Z + n * lam * np.eye(p), Z.T @ yc)
pred = y_mean + Z_test @ beta
pipe = make_pipeline(StandardScaler(), Ridge(alpha=n * lam))
pipe.fit(X_train, y_train)
np.testing.assert_allclose(pred, pipe.predict(X_test), atol=1e-9)
print("Standardized coefficients:", beta)

print("Test MAE:", mean_absolute_error(y_test, pred))
print("Test RMSE:", np.sqrt(mean_squared_error(y_test, pred)))
print("Test R2:", r2_score(y_test, pred))

plt.scatter(y_test, pred, alpha=0.7)
limits = [min(y_test.min(), pred.min()), max(y_test.max(), pred.max())]
plt.plot(limits, limits, "k--", label="Perfect prediction")
plt.xlabel("Actual target")
plt.ylabel("Predicted target")
plt.legend()
plt.tight_layout()
plt.show()

The script estimates feature scaling only on the training subset, solves the centered ridge system from scratch, reconstructs predictions, and compares them against the pipeline. The selected λ is fixed for this numerical equivalence exercise. To choose it for a real problem, use a validation search with the entire preprocessing pipeline inside each fold.

8. Practical strengths and limits

Ridge is a strong candidate when signal is spread across correlated predictors. It keeps all features in the model and often stabilizes predictions. Dense direct solvers can have costs similar to other quadratic linear systems; iterative and sparse solvers offer different trade-offs. Solver choice depends on matrix size, sparsity, and conditioning.

Ridge does not perform explicit feature selection. If collecting each feature has a substantial cost, a dense model may be inconvenient even when it predicts well. The quadratic penalty also does not make squared-error regression robust to target outliers: large residuals still receive large weight.

Preprocessing changes the penalty's meaning. Scaling on all rows leaks evaluation information, while failing to scale can cause arbitrary unit choices to determine which coefficients are penalized more severely. If some coefficients should receive different prior treatment, use an explicitly justified feature transformation or weighted penalty rather than assuming a uniform penalty is neutral.

A probabilistic interpretation of the penalty

Suppose errors are independent Gaussian with variance σ², and put independent zero-mean Gaussian priors with variance τ² on the slopes. Leave the intercept unpenalized. The negative log likelihood contributes SSE/(2σ²), and the negative log prior contributes ‖β‖²/(2τ²), apart from constants that do not affect the optimum.

\frac{\mathrm{SSE}}{2\sigma^2}+\frac{\|\boldsymbol\beta\|_2^2}{2\tau^2}\quad\Longrightarrow\quad\frac{\mathrm{SSE}}n+\frac{\sigma^2}{n\tau^2}\|\boldsymbol\beta\|_2^2

Multiplying by 2σ²/n gives this tutorial's ridge objective with λ = σ²/(nτ²). The maximum a posteriori coefficient estimate is therefore a ridge solution under these assumptions. A smaller prior variance expresses a stronger preference for slopes near zero. This is one interpretation of the penalty, not a requirement that every practical ridge model be fitted as a Bayesian analysis.

The prior is defined in the feature coordinate system. A spherical prior after standardization is not spherical in raw units. Treating preprocessing as a purely cosmetic step misses this change in the implied preference over prediction functions. Likewise, a point MAP estimate is not a complete posterior uncertainty analysis; it does not automatically provide calibrated prediction intervals.

Effective degrees of freedom

For centered data at a fixed penalty, ridge predictions are a linear transformation of the targets. Write that smoothing matrix as Hλ = X(XᵀX + nλI)⁻¹Xᵀ. Its trace measures the effective number of fitted directions in this linear-smoother sense.

\operatorname{df}_{\rm slopes}(\lambda)=\operatorname{tr}(H_\lambda)=\sum_k\frac{s_k^2}{s_k^2+n\lambda}

The singular values sₖ are those of the centered feature matrix. Each nonzero direction contributes close to one when the penalty is weak and close to zero when it is strong. With an estimated unpenalized intercept, add one for that constant direction. This is more informative than simply counting all p nonzero coefficients: a dense ridge model can have much lower effective flexibility than unregularized OLS.

This fixed-penalty expression does not account for the extra adaptivity of choosing λ by searching the data. Nor does it justify plugging p into an OLS adjusted-R² formula and calling it a complete ridge complexity correction. Use the expression to understand shrinkage, and use a properly separated validation procedure to assess the selected model.

When tuning a normalized λ, remember that each fold has its own training count. If you map to the library alpha with a full-dataset n while fitting smaller folds, you change the normalized strength. Searching library alpha directly is valid when documented, but it answers a differently parameterized selection question.

9. Interview questions

1. Why does ridge resolve singularity?

With positive λ, adding nλI makes the centered Gram matrix positive definite. Every slope direction receives positive quadratic curvature.

2. Why leave the intercept unpenalized?

Penalizing it pulls the prediction level toward zero, an arbitrary origin for many targets. Centering removes the intercept from the slope penalty naturally.

3. Does ridge always improve test error?

No. It trades bias for variance. The useful penalty depends on the sample, noise, feature structure, and deployment distribution.

4. Can ridge coefficients be exactly zero?

They can be zero due to the data or symmetry, but ridge does not generally induce exact sparsity as a consequence of its smooth penalty.

5. How does alpha relate to λ here?

For scikit-learn Ridge's sum-of-squares objective and this tutorial's MSE objective, alpha equals the training sample count times λ.

6. Why is scaling important?

The penalty acts on coefficient values, which depend on feature units. Standardization makes a unit coefficient correspond to a comparable feature-scale change.

7. Is every original coefficient monotone in λ?

No. The singular directions shrink monotonically by their factors; correlated original-coordinate coefficients can follow more complicated paths.

8. Is ridge a robust regression method?

Not in the outlier-resistance sense. Its squared residual loss can still be dominated by large target errors.

10. Practice and takeaways

  • Repeat the worked example for λ = 0, 1/3, and 2. Compare both MSE and the penalized objective.
  • Duplicate a feature and compare OLS coefficient stability with ridge under small target perturbations.
  • Search a logarithmic alpha grid inside a pipeline. Record validation mean and variability, then evaluate the selected model on a reserved test set.
  • Build a correlated-sensor prediction mini-project and document the feature units and scaling policy.

Ridge changes the optimization objective, not merely the numerical solver. Its most useful interpretation is controlled sensitivity in weakly supported directions, with an unpenalized prediction level and an explicit objective convention.
