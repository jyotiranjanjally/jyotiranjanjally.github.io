1. Compare objectives before comparing names

Ridge, lasso, and elastic net all modify least squares by penalizing coefficient magnitude. Their practical differences come from penalty geometry, objective scaling, and the feature representation. Choosing among them requires more than a rule that one is “best for many features.”

Ridge often suits distributed signal and correlated predictors. Lasso offers sparse approximations when eliminating features is useful. Elastic net combines thresholding with quadratic stabilization. Each can win or lose depending on the dataset, split, penalty, and evaluation metric.

This tutorial places all three on a common mathematical scale, works through a one-feature comparison, and implements a fair cross-validation search with an untouched test set. You should understand least squares and the basic meanings of L1 and L2 norms.

2. Put the penalties on one scale

Write a common centered-data objective with half-MSE, an L1 weight a, and an L2 weight b. This avoids confusion caused by different uses of the name alpha.

J(\boldsymbol\beta)=\frac1{2n}\|\mathbf y-X\boldsymbol\beta\|_2^2+a\|\boldsymbol\beta\|_1+\frac b2\|\boldsymbol\beta\|_2^2

The n rows are centered using training statistics, β contains slopes only, and the intercept is recovered without a penalty. Ridge sets a = 0. Lasso sets b = 0. Elastic net sets a = λρ and b = λ(1 − ρ), so λ = a + b and ρ = a/(a + b) when their sum is positive.

For ridge, multiply the common objective by 2n to obtain SSE + nb‖β‖². For lasso and elastic net, the common form already matches their library conventions. Consequently, passing the same numerical alpha to all three estimators does not create equally strong regularization.

3. Geometry and optimization behaviour

The L2 penalty is smooth and adds curvature in every coefficient direction. It improves conditioning and usually leaves nonzero coefficients. The L1 penalty is nonsmooth at zero, creating a subgradient interval that can support exactly zero coefficients. Combining them retains a threshold while increasing curvature for surviving coefficients.

The same intuition can be expressed through constrained problems: minimize residual error subject to an L1 or L2 norm budget. L1 balls have corners on coordinate axes, making sparse contact points possible. L2 balls are round, leading to smooth shrinkage. The mapping between a penalty weight and a constraint budget depends on the data and solution; they are not numerically interchangeable inputs.

On centered orthonormal features, XᵀX/n = I, let z = Xᵀy/n. The common objective separates coordinate by coordinate, yielding:

\hat\beta_j=\frac{S(z_j,a)}{1+b},\qquad S(z,a)=\operatorname{sign}(z)\max(|z|-a,0)

The threshold a determines whether a coefficient survives, while b divides its remaining magnitude. This exact special case is a useful comparison tool. For correlated features, coordinates are coupled and a one-shot threshold of OLS coefficients does not generally solve lasso or elastic net.

4. Compare predictions and errors by hand

Take x = [−1,1] and y = [−2,2]. Both means are zero, n = 2, xᵀx/n = 1, and z = 2. OLS has slope 2, predictions [−2,2], and MSE zero. Consider three explicit penalty choices on the common scale.

For ridge choose a = 0 and b = 1. The slope is 2/(1 + 1) = 1. Predictions are [−1,1], residuals [−1,1], and MSE = 1. The library Ridge alpha is nb = 2.

For lasso choose a = 1 and b = 0. The slope is S(2,1) = 1, producing the same predictions and MSE. Its library alpha is 1. Equal predictions here do not imply equivalent objectives on other datasets.

For elastic net choose λ = 1 and ρ = 1/2, so a = b = 1/2. The slope is (2 − 1/2)/(1 + 1/2) = 1. Again the predictions match. At x = 2 all three predict 2; if the true target is 4, the squared error is 4. These deliberately chosen parameters demonstrate objective mapping, not a performance ranking.

Now replace z = 2 with z = 0.4 under orthonormal scaling. Ridge at b = 1 gives 0.2; lasso at a = 1 gives zero; elastic net at a = b = 0.5 also gives zero. Weak coordinates reveal the structural sparsity difference that the first example concealed.

The chart explicitly states the objective convention for each path. Its horizontal λ values are educational parameters, not a claim of equal penalty severity. A fair predictive comparison searches each estimator's relevant range rather than assuming identical labels imply identical objectives.

6. Design a fair comparison

Reserve the test set before choosing a model. Use the same training folds and scoring rule for every candidate. Put scaling inside the pipeline. Search a reasonable logarithmic alpha range for each family, and several l1_ratio values for elastic net. Compare validation results before looking at test predictions.

For scikit-learn Ridge, alpha corresponds to an unnormalized sum-of-squares objective. If you want an experiment parameterized by a fixed mathematical λ on mean loss, account for the fold's training sample count. The example searches library alpha directly and documents that choice; it does not pretend that an identical grid represents equal normalized penalties across model families.

After selection, refit the chosen configuration on all training rows and evaluate it once on the held-out test set. The test result estimates the selected procedure's performance for that split. It should not be used to pick a different model afterward. If you require an estimate of the full model-selection process across splits, nested cross-validation is a more appropriate design.

7. One pipeline, several estimators

The script searches model family and parameters inside one grid-search object. It also fits a training-mean baseline. The printed comparison reports cross-validation performance for candidate selection and test metrics for the selected model; no test winner is used to redo selection.

"""Run with Python 3 after installing examples/requirements.txt."""
import numpy as np
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LinearRegression, Ridge, Lasso, ElasticNet
from sklearn.dummy import DummyRegressor
from sklearn.model_selection import GridSearchCV, KFold

rng = np.random.default_rng(42)
X = rng.normal(size=(300, 12))
X[:, 1] = 0.9 * X[:, 0] + 0.1 * X[:, 1]
y = 3 + X @ np.array([2, 2, -1, 0.5, 0, 0, 0, 0, 0, 0, 0, 0]) + rng.normal(0, 1, 300)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, random_state=42
)
pipe = Pipeline([("scale", StandardScaler()), ("model", Ridge())])

# These are library alpha values, not identical normalized penalties.
param_grid = [
    {"model": [LinearRegression()]},
    {"model": [Ridge()], "model__alpha": [0.1, 1, 10, 100, 1000]},
    {"model": [Lasso(max_iter=50000)], "model__alpha": [0.01, 0.1, 1, 10]},
    {"model": [ElasticNet(max_iter=50000)],
     "model__alpha": [0.01, 0.1, 1, 10], "model__l1_ratio": [0.2, 0.5, 0.8]},
]
search = GridSearchCV(pipe, param_grid, scoring="neg_mean_squared_error",
                      cv=KFold(5, shuffle=True, random_state=42), n_jobs=1)
search.fit(X_train, y_train)
pred = search.predict(X_test)
print("Selected configuration:", search.best_params_)
print("CV RMSE (sqrt of mean fold MSE):", np.sqrt(-search.best_score_))

baseline = DummyRegressor().fit(X_train, y_train)
print("Baseline test RMSE:", np.sqrt(mean_squared_error(y_test, baseline.predict(X_test))))

print("Test MAE:", mean_absolute_error(y_test, pred))
print("Test RMSE:", np.sqrt(mean_squared_error(y_test, pred)))
print("Test R2:", r2_score(y_test, pred))

plt.scatter(y_test, pred, alpha=0.7)
limits = [min(y_test.min(), pred.min()), max(y_test.max(), pred.max())]
plt.plot(limits, limits, "k--", label="Perfect prediction")
plt.xlabel("Actual target")
plt.ylabel("Predicted target")
plt.legend()
plt.tight_layout()
plt.show()

The synthetic feature matrix contains correlated columns, so it is useful for observing coefficient behaviour. It is still one controlled experiment. Change the sparsity pattern and noise level to see how conclusions depend on the generating process rather than treating one run as a universal leaderboard.

8. A practical decision framework

Start with ridge when many features plausibly carry small amounts of signal and coefficient elimination is not a requirement. Consider lasso when a sparse representation offers a concrete benefit, such as reducing feature acquisition cost. Consider elastic net when sparse selection and correlated groups both matter. Use validation evidence to challenge these starting hypotheses.

Do not rank interpretability only by nonzero count. Ten unstable selected features can be harder to defend than a dense but stable model with carefully defined inputs. Likewise, a sparse model can be operationally expensive if its few retained features are costly or delayed. Interpretation and deployment cost are properties of the entire data pipeline.

Evaluate the selection process with nested validation

Cross-validation used to choose a configuration tends to favour candidates that happened to do well on those validation samples. Reporting the best inner score as an unbiased estimate of the whole search procedure ignores that selection. Nested cross-validation adds an outer evaluation loop around the complete inner search.

In each outer split, reserve its validation fold, run the full preprocessing and hyperparameter search on the remaining rows, refit the selected configuration there, and predict the outer fold. Only the outer predictions are used to estimate the selection procedure's performance. Different outer folds may select different families or penalties; that variability is useful information about how decisively the data distinguishes candidates.

Nested validation increases computation substantially. With K outer folds, L inner folds, and C candidate configurations, fitting work is roughly proportional to KLC, plus refits, although implementation details and warm starts can alter actual cost. Use it when its additional evidence matters, rather than assuming every small prototype requires the most expensive possible evaluation.

Compare stability at the right level

There are several distinct kinds of stability: selected feature sets, coefficient values, rankings of predictions, and absolute prediction values. A lasso model can switch between duplicate features without materially changing its predictions. A ridge model can retain all features while its predictions shift under distribution change. State which stability matters for the application before choosing a measurement.

For feature-selection stability, use repeated training resamples and report inclusion frequencies or overlap. For prediction stability, evaluate models trained on those resamples on a fixed reference set that represents the operating domain. Do not use that reference set's targets to pick the most stable-looking model unless it belongs inside the validation design.

Interpret a small score difference alongside operational cost

Suppose two candidates have close validation RMSE but one requires a delayed feature unavailable during a real-time request. That candidate may fail the prediction contract regardless of its score. Another may rely on a costly external measurement whose price exceeds the value of its modest error reduction. A useful model comparison includes these constraints explicitly.

A defensible report can say that several candidates were statistically or practically competitive and choose the simpler deployable option using a prespecified rule. Avoid claiming that the selected estimator is universally superior. The conclusion should be limited to the evaluated procedure, population, metric, and data volume.

Finally, separate a model family from its tuned instance. “Ridge lost” can mean only that the particular feature representation, scaling, grid, solver, and selection process did not win this comparison. It does not establish that every ridge configuration or every linear representation is unsuitable for the problem.

9. Interview questions

1. Can identical alpha values be compared across these estimators?

Not as identical penalty strength. Ridge uses a sum-of-squares convention, while Lasso and ElasticNet use half-MSE. The parameter mapping must account for normalization.

2. Which method removes features?

Lasso and elastic net with a positive L1 component encourage exact zeros. Ridge generally shrinks without selecting an exact subset.

3. Why might ridge beat lasso on dense signal?

When many small effects matter, eliminating them can add excessive bias. Quadratic shrinkage can retain their collective contribution.

4. Why might elastic net help with correlated features?

Its L2 term adds curvature and discourages concentrating all effect in one interchangeable feature, while the L1 term still allows sparsity.

5. Is thresholding OLS always a lasso solver?

No. It gives the solution in the orthonormal special case. Correlated design columns couple the optimization coordinates.

6. What makes a model comparison unfair?

Different test rows, leakage in only some pipelines, unequal tuning opportunities, mismatched metrics, or using the test set to choose the winner.

7. Should a selected sparse model be refit with OLS?

It is an optional different procedure. It can reduce shrinkage bias and increase variance; the entire selection-and-refit pipeline must be validated.

8. Is a small validation advantage decisive?

Not necessarily. Inspect fold variability, stability, operational complexity, and whether the difference is meaningful for the decision.

10. Exercises and takeaways

  • Translate a = 0.2 and b = 0.8 into elastic-net λ and ρ, then map the pure-L2 part to a Ridge alpha for n = 100.
  • Run the comparison on sparse and dense synthetic signals while preserving the same evaluation procedure.
  • Compare coefficient stability across resamples separately from predictive accuracy.
  • Write a model-selection memo that includes feature cost, validation variability, and the exact objective convention.

Choose the procedure whose validated behaviour matches the problem. Penalty names are starting points; objectives, data representation, and credible evaluation make the comparison meaningful.
